# 每日研究精读

原 daily-brief 改为每天一篇研究资料带读，替代新闻、基金和活动。技术报告、普通学术论文、System Card、官方技术长文均可入选，不以发表形式或是否出自大厂排除有学习价值的材料。仍使用原 GitHub Actions 任务与 SMTP Secrets；计划时间为北京时间每天 07:00，GitHub 可能延迟调度。

每封包含原文、选择理由、关键机制、建议章节、面试自测题和一个小练习。按知识缺口相关性优先，同等相关性再选更新报告。经典报告保留原发布日期，不冒充新闻。导读经过原文核验，运行时检查原文链接和标题；不从标题自动编造报告内容。

## 内容维护

reports.json 是可维护的已核验阅读池，config.yaml 保存一般学习主题与更新日期。每篇有稳定 ID（arXiv ID 或自定标识）、原文版本、发布日、核验日、优先级、章节和导读。新增材料先读原文，校核机制与章节，再加入；相关性可随学习进展调整。优先补当前面试与知识缺口，也保留基础、跨领域联系和探索性阅读，不只追逐热门或最新文章。公开仓库不得放入面试逐字稿、公司内部信息、私人批注或未公开研究。

arXiv、企业和实验室官方研究页面、作者原文均可作为来源。Hugging Face Papers、arxivdaily、智源及媒体汇总用于发现线索，导读回到原始资料核验。不要按标题、有无理论证明或消融实验机械过滤论文；GPT-4 等报告未公开的训练细节不得补写。

原文支持 HTML 与 PDF。HTML 默认用 title 核验正文，可用 source_title 指定原文实际标题；PDF 设置 source_format 为 pdf，并记录已阅读原件的 pdf_sha256，内容变化时暂停发送以重新核验。跨域跳转须在 redirect_hosts 明确登记已核验的目标主机。来源真实性由选题时核验，HTTPS 与标题匹配只用于发送前的链接检查，不能替代原文阅读。

每日发送程序本身不读取本地知识库，也不调用付费模型。知识库变化与新资料的选题维护由另行配置的 Codex 跟进任务执行，其运行依赖本机和应用可用；即使维护离线，GitHub 仍可发送已核验阅读池。阅读池全部发过后明确标注“间隔复习”，不伪称发现新报告。选题超过 14 天未更新会在邮件中提示。

## 发送与验证

原 SMTP_HOST/PORT/USERNAME/PASSWORD/FROM Secrets 继续生效，收件人限定为配置中的既定邮箱。只发邮件。SMTP 接受并不等于已证实收件箱送达。

delivery-state.json 记录成功发送日期与报告 ID。工作流串行运行并将发送状态提交回仓库，同一天重跑会跳过。预览和失败均不推进状态。SMTP 接受后、状态持久化前若发生中断，存在重发窗口；发生此类故障应先查日志与邮箱，再决定是否重跑。

本地安装 requirements.txt 后，运行 python -m unittest -v test_reports.py 验证，再用 python main.py --preview 生成预览。

Actions 手动运行选 no-send 可预览，选 send 发送。预览产物在该次运行的 daily-brief-html artifact 中。原简报源文件仍保留用于历史恢复，主程序已不调用。
